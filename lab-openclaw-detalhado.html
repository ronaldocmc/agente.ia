OpenClaw — laboratório de Gateway, sessão e skill

Versão expandida: abrir implementação detalhada, com roteiro de execução e testes →

Quem orquestra? O Gateway recebe mensagens e gerencia canais/sessões; o runtime do agente executa o ciclo com modelo e ferramentas. A skill instrui como consultar dados. FastAPI e PostgreSQL não são substituídos por OpenClaw.

Resposta e log

1. Objetivo e resultado

Receber a pergunta “Quantas vagas há em Agentes de IA?”, consultar um catálogo fictício e responder 30 vagas, com origem identificada. A resposta não pode inventar dados nem executar alterações externas.

2. Dados e arquitetura da experiência

Os arquivos comuns ficam em laboratorios/comparacao-seis-abordagens/: catalogo.json, regras.py, consultar.py e SKILL.md. A regra de negócio é executada por código, nunca decidida pelo prompt.

3. Instalação

Consulte requisitos de Node.js no guia oficial (mudam por versão). Em um ambiente de teste isolado, siga o onboarding documentado:

node --version
npx openclaw@latest
# após concluir o setup
openclaw gateway status

4. Criar capacidade

Use o SKILL.md do laboratório e um workspace restrito. Consulte o mecanismo de instalação de skills documentado pela sua versão. Não habilite shell com acesso irrestrito ao computador pessoal. O objetivo é demonstrar seleção de procedimento e retorno de dados sintéticos.

python consultar.py "Agentes de IA"

5. Testes esperados

Pergunte sobre Agentes de IA e curso inexistente; verifique logs de ferramenta. Teste um pedido de apagar arquivos: a execução deve ser negada por política externa, não apenas por prompt.

6. Erros e segurança

Gateway offline: verifique serviço e porta. Sem resposta: valide credenciais do modelo. Skill não carregada: confira paths e configuração. Para produção: vinculação de canais, allowlists, segregação de identidade, sandbox, auditoria e aprovação humana.

7. Quando usar

Escolha OpenClaw quando Gateway, canais e sessões persistentes forem requisitos reais. Se só houver formulário/agenda, n8n + FastAPI pode ser mais simples. Execução real do runtime não foi testada aqui.

Roteiro de implementação verificável — OpenClaw

O que será construído?

Assistente multicanal com skills. O caso comum utiliza informações fictícias de cursos; não envia dados institucionais reais.

Arquitetura e responsabilidades

Solicitação simulada
        ↓
OpenClaw — coordenação / ambiente de execução
        ↓
Ferramenta consultar_curso (lógica determinística)
        ↓
Resultado validado → registro → resposta

O Gateway mantém canais/sessões; o runtime do agente decide ferramentas; a API institucional aplica permissão. O Gateway roteia mensagens e sessões; o agente escolhe ações, mas o backend deve autorizar cada ferramenta.

Pré-requisitos e arquivo do projeto

Antes de instalar, verifique versão da documentação oficial, Python ou Docker quando indicado, permissões restritas e custos do provedor. Artefato de apoio: laboratorios/lab18_multiplataforma/openclaw/SKILL.md. O código encontra-se no pacote do Agente.IA.

Instalação e execução orientada

Instale o OpenClaw segundo a documentação vigente; configure inicialmente um ambiente local sem canais públicos; prepare a skill SKILL.md; teste em uma sessão com dados fictícios; conecte canais apenas após verificar identidades e políticas de execução.

Resultado esperado e testes

Teste A: curso conhecido → dados correspondentes ao catálogo; teste B: curso desconhecido → sinalização de inexistência; teste C: tentativa de consultar documento não autorizado → bloqueio, sem execução privilegiada. Registre também quais ferramentas foram realmente chamadas.

Erros frequentes

Plugins, skills e canais têm superfícies de ataque distintas; inicie com permissões mínimas e aprovações.

Segurança e avaliação

Princípio de menor privilégio, dados fictícios, segredos fora do código, aprovação de ações sensíveis e logs sem dados pessoais. O modelo não define nem altera regras de autorização. Compare cada resposta com o baseline determinístico.

Status: este roteiro descreve a implementação e os critérios de aceitação; não é evidência de execução real do runtime neste ambiente. Consulte o índice de laboratórios e a matriz de decisão.
