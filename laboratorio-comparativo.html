Laboratório experimental: agente direto × skill

Laboratório experimental · Python 3 · dados sintéticos

Procedimento direto × procedimento encapsulado em skill

Compare duas arquiteturas equivalentes sem confundir organização de código com melhoria comprovada de IA. O experimento fixa o mecanismo de decisão, varia a encapsulação procedural e registra qualidade, custo operacional, reprodutibilidade e segurança.

1. Pergunta de pesquisa e hipótese

Pergunta: encapsular consultar_certificado em uma skill versionada reduz defeitos de integração e melhora a reprodutibilidade sem alterar a regra institucional?

H0: não existem diferenças mensuráveis de qualidade, custo, reprodutibilidade ou segurança sob as condições testadas. H1: ao menos uma dimensão difere. É possível não observar diferença; o laboratório não pressupõe superioridade da skill.

2. Três baselines para não atribuir ganhos indevidos

VersãoExecuçãoFunção
A — diretaAgente/roteador chama rotina programada diretamenteBaseline procedural
B — skillAgente/roteador seleciona contrato/skill que chama a mesma rotinaIsolar efeito de encapsulação e versionamento
C — workflowRoteador determinístico chama a mesma funçãoVerificar se um agente é realmente necessário

No pacote executável, A e B usam o mesmo algoritmo para impedir que mudanças da lógica expliquem diferenças. C é uma extensão de projeto. Para comparar LLMs de verdade, implementar outro braço mantendo modelo, temperatura, corpus, ferramentas, orçamento e política fixos; registrar versões e repetições.

3. Cenário e regra institucional

Um participante solicita informações de certificado. O agente recebe identificador, módulo e turma e consulta dados sintéticos. A regra do M12 utiliza frequência mínima de 75%, mas o laboratório exige, além disso, que a inscrição esteja identificada e que o status seja consistente. A LLM não decide elegibilidade.

Entrada: JSON com email, modulo, turma, actor; saída: apto, pendente, nao_apto ou nao_localizado; falhas retornam erro categorizado. Dados de outro participante devem ser negados.

4. Como executar

cd laboratorios/lab17_skill_vs_direto
python3 experimento.py
python3 -m unittest discover -v

Requer somente Python 3.10+ e biblioteca padrão, sem tokens, contas pagas ou acesso a sistemas reais. O script gera resultados.csv, resumo.json e comparacao.md. A primeira comparação usa custos simulados de chamadas, distintos de valores monetários reais.

5. Métricas e critérios

DimensãoMétricaComo interpretar
QualidadeAcurácia do status e taxa de respostas válidasComparar com gabarito independente
CustoChamadas de ferramentas, LLM e custo estimado por tarifa declaradaSem conversão monetária na simulação
ReprodutibilidadeSaídas idênticas em repetição com versão e dados fixosDistinguir mesma saída de reprodução completa
SegurançaTaxa de bloqueio de acesso indevido e resistência a instrução maliciosaBloqueio imposto pelo código/serviço, nunca só pelo prompt
ManutenibilidadeQuantidade de pontos de alteração e contratos reutilizadosMedição manual em tarefas de mudança

6. Plano de experimento

  1. Definir conjunto de casos e gabarito antes de executar os braços.
  2. Congelar dados sintéticos, esquema de saída, políticas e código de negócio.
  3. Executar braço A e B sobre os mesmos casos; repetir em ordens alternadas.
  4. Executar ataques controlados: pedido por dados alheios, instruções maliciosas e entrada inválida.
  5. Comparar acurácia, violações, custo de ferramenta, tempo e estabilidade do resultado.
  6. Para pesquisa com LLM, usar amostra suficiente, replicações, intervalos de confiança e análise de casos de falha; descrever ameaças à validade.

7. Tradução para n8n

A: Manual Trigger → Edit Fields → IF → Sheets → resposta → log. B: fluxo principal → Execute Workflow skill_consultar_certificado → resposta → log. C: mensagem → LLM classifica intenção → agente seleciona tool autorizada → sub-workflow → resposta. O fluxo C exige testes adicionais de seleção de capacidade e prompt injection; a regra objetiva continua fora do LLM.
