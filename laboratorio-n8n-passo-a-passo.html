Meu primeiro workflow n8n — passo a passo

Tutorial principal: percurso atualizado por tecnologia. Este material permanece como exercício complementar.
Novo tutorial didático: n8n — do zero à primeira solução. Comece pelo passo a passo, depois utilize este laboratório complementar.

Da automação visual ao agente: instale, importe, execute, teste e decida quando usar LLM.

1. O que você vai construir

Um fluxo com gatilho manual → entrada sintética → regra de certificado → resultado. A regra é determinística: o modelo de linguagem não decide se um aluno está apto.

Aprendizagem: diferenciar automação, orquestração, uso de ferramentas e skill.

2. Instalar o ambiente

Pré-requisitos: Docker Desktop/Engine e navegador moderno. Use instalação local, sem publicar o servidor na Internet.

docker run --rm -it --name unesp-n8n -p 5678:5678 -v unesp_n8n_data:/home/node/.n8n docker.n8n.io/n8nio/n8n

Abra http://localhost:5678 e conclua a configuração de conta se necessária. Veja a documentação oficial do n8n para Docker. Os comandos podem mudar conforme a versão da plataforma.

3. Importar o workflow

  1. No n8n, crie um workflow e escolha Import from File.
  2. Selecione laboratorios/n8n-primeiro-workflow/workflow-certificados.json (dentro da pasta extraída).
  3. Confira os nós Iniciar (manual), Pedido sintético e Regra institucional (determinística).
  4. Clique em Execute workflow e abra o resultado do último nó.

Artefato original: Abrir workflow JSON.

4. Executar três cenários e verificar o resultado

Entrada sintéticaResultado esperadoExplicação
Ana, frequência 90%, situação regularaptoAtende ao limiar demonstrativo de 75%
Bruno, frequência 60%, situação regularnao_aptoFrequência abaixo do limiar

Para mudar o cenário, edite o objeto no nó Pedido sintético. A proteção por comparação de strings é apenas uma simulação didática, não autenticação real.

5. Quando isso se torna um agente?

Este exemplo é uma automação, não um agente de IA. Para experimentar um comportamento agêntico, acrescente interpretação da solicitação por LLM (por exemplo, Ollama local via HTTP Request) e seleção limitada de ferramentas. O resultado do LLM deve ser validado antes da execução. Nunca delegue ao LLM a política de frequência, a identidade ou a autorização.

Leia laboratórios multiplataforma e escolha tecnológica para comparar com SDKs e agentes.

6. Erros frequentes

SintomaVerificação
Não abre localhost:5678Contêiner parado, porta ocupada ou firewall
Nó Code falhaVersão do n8n ou JavaScript alterado; reveja o código do nó
Importação falhaUse o JSON do workflow, não o arquivo de cenários
Ollama inacessível no contêinerUse endereço de rede alcançável e permissão explícita; localhost do contêiner é diferente do host

7. Segurança e avaliação

Registre resultado, versão, data, erros e tempo. Teste entrada inválida, tentativa de alterar ator, acesso indevido e falha do serviço. Não exponha endpoints sem autenticação ou credenciais em logs. Consulte guardrails.

Validação: o JSON foi examinado e a lógica é equivalente ao laboratório Python existente; a importação em n8n real permanece para o aluno testar.
