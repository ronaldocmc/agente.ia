Ficha técnica e percurso de aprendizagem

Escopo: aprofundamento didático; exemplos propostos com dados sintéticos. A existência de uma ficha não comprova execução no produto.

1. Conhecer — finalidade e papel

Plataforma de automação visual de workflows, que integra APIs, serviços, bancos e modelos. Pode executar fluxos fixos e, com nó de agente e tools, decisões condicionadas ao LLM.

2. Compreender — componentes

Triggers Manual, Schedule e Webhook; nós de transformação Edit Fields e Code; IF/Switch; HTTP Request; credenciais; histórico de execuções; nó AI Agent, modelo de chat e tools; memória opcional.

3. Compreender — arquitetura e execução

Trigger inicia uma execução; cada nó recebe itens JSON e produz itens para o próximo. O workflow é orquestrado pelo n8n; em um nó de agente, o modelo pode escolher tools oferecidas, e o runtime administra o ciclo. O LLM não substitui as regras do fluxo.

4. Comparar — decisão tecnológica

Make/Zapier para conectores gerenciados; LangGraph/Agents SDK para controle programático de estado e ferramentas. n8n pode integrar ambos.

5. Preparar e implementar — prática orientada

Pré-requisitos: acesso ao produto ou ambiente indicado na documentação oficial; conta de teste, dados fictícios, permissões mínimas e versões registradas. Não é necessário contratar serviço para estudar a arquitetura. A execução real pode exigir conta, instalação ou cobrança.

Roteiro: Manual Trigger → Edit Fields com solicitacao=certificado → Switch → resposta simulada. Evoluir para AI Agent + modelo compatível + tool de consulta de certificado, usando apenas dados fictícios.

  1. Documentar o objetivo, entradas, saídas e identidade autorizada.
  2. Configurar somente os componentes necessários conforme a documentação e executar primeiro o caminho nominal.
  3. Registrar resultado, versão, tempo, etapas executadas e eventuais custos; não confundir execução simulada com integração real.

Exemplo ampliado: automação versus agente

Fluxo fixo: Manual Trigger → Edit Fields → Switch → Edit Fields (resposta). Crie três casos: certificado, matrícula e desconhecido. Use um ramo padrão para a última categoria. Nenhum LLM é necessário.

{"id":"REQ-001","categoria":"certificado","texto":"Como obter meu certificado?"}

Saída esperada para o exemplo: {"id":"REQ-001","rota":"certificado"}. No ramo desconhecido, encaminhar à revisão humana. No editor, execute cada nó e inspecione o JSON de entrada e saída.

Fluxo com LLM: substitua a classificação por uma chamada a modelo, valide o JSON e mantenha Switch fixo. O modelo interpreta; o workflow continua decidindo o fluxo.

Agente: adicione AI Agent, modelo de chat compatível (por exemplo Ollama se o modelo suportar tool calling), e uma ferramenta de consulta somente leitura. Defina a ferramenta com argumentos tipados e limite de iterações. O agente decide se chama a ferramenta; o backend valida o identificador e autorização. Memória de conversa é opcional e não substitui armazenamento de evidências.

Consulte os roteiros completos: n8n + Ollama, laboratório detalhado e workflow × agente. Instalação local ou Cloud são alternativas; registre a versão e não exponha webhooks de teste à internet sem proteção.

6. Testar — critérios de aceitação

Entrada sem campo, solicitação desconhecida, timeout, tool desautorizada e duplicação de evento. Validar esquema, configurar erros e idempotência; credenciais fora do JSON exportado.

CenárioCritério esperado
Entrada nominalResultado atende à tarefa definida e pode ser conferido com o dado sintético de origem.
Entrada incompleta ou inconsistenteSolicita correção ou informa falha; não inventa dados nem executa efeitos indevidos.
Operação fora do escopoNão concede acesso nem produz efeito externo sem autorização.
ReexecuçãoRegistrar diferenças; para operações com efeitos, evitar duplicações.

7. Aplicar — integração institucional

Reutilizar a prática em um cenário de educação ou Observar.IA, mantendo identificação da origem, delimitação das permissões, revisão humana de ações críticas e registro de evidências. A tecnologia deve ocupar somente o papel arquitetural descrito acima.

8. Evoluir — próximos estudos

Compare a solução com as alternativas descritas, documente a necessidade de adicionar autonomia, ferramentas ou integração e avalie se a complexidade adicional é justificada. Para ferramentas auxiliares, evoluir a integração, não atribuir autonomia artificialmente.

Material: Documentação primária · Laboratório ou estudo complementar · Auditoria curricular · Painel de evidências.

Validação: aprofundamento editorial; execução específica deste roteiro não realizada nesta revisão.

Percurso técnico por função: n8n

Perfil didático: Implementação prioritária. Papel: Workflows, execução de nós e AI Agent. Este roteiro é proposto; os testes específicos não foram executados nesta revisão.

1. Conhecer e compreender — arquitetura e responsabilidades

Trigger → itens JSON → nós e ramificações → resultado. AI Agent utiliza modelo e tools como componentes; autorização e validação permanecem nas ferramentas/backend.

2. Comparar — critérios de seleção

Make/Zapier oferecem automação gerenciada; LangGraph e SDKs permitem maior controle por código; Ollama fornece inferência, não fluxo.

3. Preparar — requisitos e limites

Instalar n8n ou usar conta de teste; montar Manual Trigger → Edit Fields → Switch primeiro. Para agente, adicionar modelo compatível e tool de leitura; registrar versão e não exportar segredos.

4–5. Preparar e implementar — atividade de aprendizagem

Experimento: Construir workflow fixo com Switch e versão com AI Agent e ferramenta somente leitura.

Sequência orientada: REQ-001 classificado por regra versus por LLM versus agente que consulta a ferramenta. Comparar trajetórias e resultados, não apenas texto final.

{"id":"REQ-001","solicitacao":"certificado","status_esperado":"apto"}

O registro acima é dado sintético de referência, não resposta obtida de um runtime. Use uma ferramenta local de consulta que aceite somente o identificador e devolva o status. O backend deve impor autorização independentemente da instrução do agente.

  1. Identifique a versão da tecnologia e o componente que será exercitado; prepare um ambiente isolado ou, para padrões e métodos, uma representação documental de teste.
  2. Execute a atividade descrita com dados sintéticos e registre entrada, configuração e saída observada.
  3. Repita com o cenário de falha da tabela abaixo; registre diferenças em vez de atribuir aprovação sem execução.

6. Testar — critérios específicos

CenárioCritério de aceitação
NominalConstruir workflow fixo com Switch e versão com AI Agent e ferramenta somente leitura.
Falhas e limitesComparar trilhas de execução; testar duplicação, autorização e JSON inválido.
ReproduçãoReexecutar com mesmas versões e dados; documentar artefatos, diferenças, custo quando disponível e limitações. Repetições idênticas não são garantidas para modelos probabilísticos.

7. Aplicar — integração com o Agente.IA

Use a atividade como componente de uma solução de consulta, coleta, curadoria ou avaliação, conforme seu papel. Vincule a execução à tarefa, à tecnologia e ao resultado; não atribua ao componente funções que ele não implementa.

8. Evoluir — próximos passos

Adicionar persistência, ferramentas, delegação ou rotinas uma por vez; comparar cada evolução com a implementação mínima e registrar a diferença de custo, qualidade e segurança.
