Meu primeiro agente: do zero à execução

Quer criar agentes em plataformas prontas? Após concluir este laboratório de base, compare Grok Bot, OpenClaw, Hermes e dots. Veja quando escolher cada um e o laboratório de equipes de agentes. O percurso com Python/Ollama continua sendo a referência reproduzível sem assinatura comercial obrigatória.

Comece aqui: roteiro para alunos que nunca construíram um agente. Primeiro entenda o ciclo; depois execute o código sem custo de API externa e, por fim, conecte um modelo local.

O que você vai construir

Um agente didático que responde sobre dois cursos fictícios. Ao receber “Quantas vagas há no curso de agentes?”, o modelo decide consultar a ferramenta consultar_curso; a ferramenta devolve dados estruturados e o modelo elabora a resposta.

Por que esse exemplo? Não exige credenciais, banco ou WhatsApp. Ele permite ver claramente a diferença entre chatbot, automação e agente com ferramenta.

Passo 1 — Preparar o ambiente

Instale Python 3.10 ou superior. Abra um terminal na pasta Wiki_unespIA/laboratorios/primeiro-agente/. No Windows, experimente py --version e use py no lugar de python se necessário.

python --version
python testes.py

Resultado esperado: 6 testes executados, todos aprovados (OK).

Passo 2 — Entender o ciclo sem LLM

python offline.py

Digite Quantas vagas há no curso de agentes?. A simulação identifica o curso e consulta os dados. Observe os arquivos ferramentas.py (a operação autorizada) e offline.py (o roteamento por regras).

Importante: nesta etapa há automação determinística, não um agente com modelo de linguagem. O objetivo é construir um baseline verificável.

Passo 3 — Transformar em agente com Ollama

Instale o Ollama. Escolha um modelo que suporte tool calling; o exemplo usa qwen3:4b (ajuste conforme hardware e disponibilidade).

ollama pull qwen3:4b
python agente_ollama.py

Se o serviço não estiver ativo, inicie ollama serve em outro terminal. O código envia ao modelo a especificação da ferramenta. O modelo pode escolher uma chamada, a aplicação valida os argumentos e executa somente a função permitida.

Observe no resultado o campo ferramentas_executadas. Se estiver vazio, verifique a versão do Ollama, o modelo utilizado e a formulação da pergunta. A execução com Ollama é um exercício a validar no computador do aluno.

Passo 4 — O que acontece internamente?

  1. O usuário envia uma pergunta.
  2. O LLM recebe instruções e a descrição da ferramenta.
  3. Se necessário, o LLM solicita consultar_curso.
  4. O executor valida nome e argumentos contra uma lista permitida.
  5. O resultado volta como mensagem de ferramenta.
  6. O LLM produz a resposta final, fundamentada no resultado.

A autorização é implementada no código. Um prompt dizendo “não faça operações perigosas” não substitui as verificações.

Passo 5 — Testar e avaliar

Teste: pergunta conhecida, curso inexistente, pedido ambíguo, chamada de ferramenta proibida e tentativa de adicionar argumento não autorizado. Registre se o agente consultou dados, se respondeu corretamente e se respeitou limites.

Para a avaliação científica, repita cenários em modelos diferentes mantendo as mesmas ferramentas e os mesmos dados. Não confunda testes locais da lógica com testes de segurança do runtime ou da implantação.

Passo 6 — E agora?

Após conseguir a primeira consulta, evolua gradualmente: (1) extrair procedimento para skill; (2) adicionar dados em PostgreSQL; (3) iniciar tarefas por n8n; (4) implementar múltiplos agentes usando CrewAI ou LangGraph; (5) desenvolver aplicações do catálogo de casos.
