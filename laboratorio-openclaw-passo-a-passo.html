OpenClaw — Gateway, canais e skills

Novo tutorial didático: OpenClaw — do zero à primeira solução. Comece pelo passo a passo, depois utilize este laboratório complementar.

Problema comum: triagem e consulta de cursos fictícios. Competência: Assistente multicanal auto-hospedável. A regra de negócio nunca é decidida pelo LLM.

1. O que será construído e por quê

Levantar Gateway de laboratório, registrar uma skill e testar mensagens locais sem vincular WhatsApp real.

Exemplo: Agente atende solicitações de curso em canal isolado.

Entregável: registro da configuração, execução, resposta, resultado dos testes e análise das limitações.

2. Ambiente e instalação

Node.js compatível com a versão oficial, máquina de teste/VM, provedor de modelo configurado. Seguir onboarding e habilitar somente canais locais inicialmente.

Baixe o pacote completo e abra Wiki_unespIA/laboratorios/avancados/README.md. Ambiente-base:

python --version
cd Wiki_unespIA/laboratorios/avancados
python testes.py
python baseline.py

O código comum usa somente a biblioteca padrão Python. As instalações externas são opcionais e dependem de verificação da versão e das condições do provedor.

3. Arquitetura e responsabilidades

Fluxo: solicitação → validação de entrada → seleção da capacidade → consulta autorizada → revisão → resposta com fonte → log e avaliação. Guardrails e memória são transversais; não substituirão a fonte oficial.

Fronteira: o agente pode selecionar um procedimento; a função consultar_curso controla acesso e fatos retornados. Arquivos de domínio são apenas sintéticos.

4. Código ou configuração explicados

Arquivo: skills/consultar-curso/SKILL.md (o pacote inclui código comentado ou instruções que podem ser reproduzidas).

npx openclaw@latest  # onboarding; não conecte canais/contas reais no laboratório

Leia o conteúdo do arquivo antes de executar. Para integrações hospedadas, adapte permissões, disponibilidade de modelo e limite financeiro; nunca copie segredos para o Agente.IA.

5. Execução e resultado esperado

O Gateway responde em sessão de teste; o agente identifica a skill e explica que não tem acesso a cursos além dos dados explicitamente fornecidos.

Comece com python testes.py e python baseline.py. Depois execute o comando do roteiro, se o ambiente e a conta suportarem a tecnologia. Registre logs e divergências sem incluir dados pessoais.

6. Erros comuns e como corrigir

  • Node incompatível: conferir requisito de versão na documentação oficial.
  • Gateway não abre: executar diagnóstico e inspecionar portas/credenciais sem expor tokens.
  • Skill descoberta mas não executa consulta: SKILL.md não instala ferramenta Python automaticamente.

7. Segurança e guardrails

Use dados de demonstração; desative conexões reais, escrita e envio externo; aplique allowlist por ferramenta, limites de execução e autorização fora do prompt. Nunca considere a resposta do agente como autorização para modificar sistemas.

Testes mínimos: acesso por usuário inválido, curso não existente, texto malicioso em dados e ação não permitida. Veja Segurança e guardrails e Skills.

8. Avaliação e comparação científica

Registre: versão da tecnologia, modelo, prompt, entrada, saída, custo, tempo de resposta, taxa de acerto, aprovações, falhas de ferramenta e rastreabilidade. Compare com o baseline determinístico e não declare superioridade sem repetição e critérios comuns.

Quando escolher: Escolha OpenClaw quando canais, sessões e Gateway próprios forem requisitos centrais; avalie controle e superfície de ataque.

Alternativas: Hermes para ambiente de agente e skills; Grok Bot para equipes gerenciadas; n8n para automações orientadas a eventos.
