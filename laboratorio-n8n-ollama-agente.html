Laboratório executável de referência

n8n + Ollama: construindo um agente com ferramentas

Este laboratório compara workflow determinístico e agente com escolha dinâmica de ferramenta. Utiliza apenas dados fictícios; não depende de assinatura de API. A importação real ainda precisa ser validada na instalação do aluno.

1. Arquitetura

Chat Trigger → AI Agent (n8n) ← Ollama Chat Model (qwen3:4b) + Custom Code Tool consultar_curso. A ferramenta mantém a regra de negócio fora do prompt.

2. Instalação

  1. Instale Docker e Ollama. No terminal execute ollama pull qwen3:4b.
  2. Extraia o ZIP do Agente.IA e acesse laboratorios/n8n-ollama-agente/.
  3. Execute docker compose up -d e abra http://localhost:5678.
  4. Importe o arquivo workflow-n8n-agente-ollama.json.
  5. Configure a credencial Ollama apontando para http://host.docker.internal:11434 quando o n8n estiver em Docker e Ollama instalado no host.
  6. Abra o chat do workflow e teste as perguntas abaixo.

3. Testes didáticos

PerguntaComportamento esperado

4. O que observar na execução

Verifique no histórico se o modelo chamou a ferramenta, os parâmetros enviados, a saída retornada e a resposta final. Sem chamada de ferramenta, a resposta não é considerada validada.

6. Erros comuns e segurança

Falha na conexão: endereço localhost dentro do Docker aponta para o próprio contêiner, não para o host. Sem chamada de ferramenta: confira o suporte do modelo a tool calling, o vínculo ai_tool e a descrição da ferramenta. Dados incorretos: nunca permita que o LLM determine regras ou direitos institucionais. Produção: autenticação, políticas, logs, redes privadas e aprovação humana são obrigatórios.

7. Aplicação ao Escritório Virtual

Troque a consulta sintética por uma API FastAPI autenticada de documentos institucionais, somente leitura. Mantenha n8n para agendamento, FastAPI para autorizações e PostgreSQL para dados e auditoria. Veja a decisão arquitetural do Escritório Virtual.
