Agents SDK para Python — laboratório completo

Tutorial principal: percurso atualizado por tecnologia. Este material permanece como exercício complementar.

Laboratório ampliado: execução guiada, passo a passo

Estado: roteiro preparado e auditável; execução real com serviço ou runtime externo precisa ser feita na máquina de estudo. Utilize dados sintéticos e registre logs.

  1. Prepare Python: verifique python --version e utilize Python 3.11 ou superior.
  2. Localize os arquivos: abra laboratorios/comparacao-seis-abordagens/ e leia catalogo.json, regras.py e agents_sdk.py.
  3. Crie ambiente isolado: execute python -m venv .venv e ative o ambiente virtual.
  4. Instale: execute pip install openai-agents. Não coloque chaves nos scripts nem no ZIP.
  5. Configure acesso: defina OPENAI_API_KEY no ambiente do terminal, sem exibir a chave em capturas de tela.
  6. Teste baseline: execute python teste_baseline.py para verificar as regras antes da chamada ao modelo.
  7. Execute: rode python agents_sdk.py. O programa cria Agent, registra a função buscar_curso e executa Runner.run.
  8. Inspecione: verifique se a ferramenta foi chamada e se a resposta depende do catálogo; repita os testes com pedidos adversariais.

Quem orquestra? Runner administra o ciclo modelo → ferramenta → modelo. O SDK não substitui autenticação, política institucional ou persistência.

Como verificar que realmente funcionou

  1. Registre a versão instalada, a data e o modelo utilizado.
  2. Faça uma pergunta sobre o curso fictício “Agentes de IA”: compare as vagas obtidas com catalogo.json.
  3. Faça uma pergunta sobre curso inexistente: resposta deve indicar ausência, não inventar dados.
  4. Solicite uma ação não autorizada (por exemplo, alterar vagas): o agente deve recusar ou pedir confirmação sem executar alteração.
  5. Guarde apenas logs sem dados pessoais: entrada, ferramenta chamada, resultado da ferramenta, resposta final, duração e custo, quando aplicável.

Avaliação: acurácia, chamadas corretas de ferramenta, contenção de ações não autorizadas, latência e reprodutibilidade. O baseline sem LLM é o comparador de referência.

1. Objetivo e resultado

Receber a pergunta “Quantas vagas há em Agentes de IA?”, consultar um catálogo fictício e responder 30 vagas, com origem identificada. A resposta não pode inventar dados nem executar alterações externas.

2. Dados e arquitetura da experiência

Os arquivos comuns ficam em laboratorios/comparacao-seis-abordagens/: catalogo.json, regras.py, consultar.py e SKILL.md. A regra de negócio é executada por código, nunca decidida pelo prompt.

3. Instalação

Python 3.11+ e chave de API de provedor compatível. Laboratório opcional com serviço externo; pode haver cobrança por tokens.

python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
pip install openai-agents
$env:OPENAI_API_KEY="SUA_CHAVE"
python agents_sdk.py

4. Código que será executado

O arquivo agents_sdk.py importa Agent, Runner e function_tool; a ferramenta retorna JSON sintético. O script completo está no pacote.

"""Exemplo: pip install openai-agents. Precisa OPENAI_API_KEY e custos de API."""
import asyncio, json, os
from agents import Agent, Runner, function_tool
from regras import consultar_curso
@function_tool
def buscar_curso(nome: str) -> str:
    """Consulta SOMENTE o catálogo fictício; forneça o nome exato do curso."""
    return json.dumps(consultar_curso(nome),ensure_ascii=False)
agent=Agent(name='Consulta educacional',instructions='Para qualquer pergunta sobre curso, use buscar_curso. Não invente valores. Nunca envie mensagens nem altere dados.',tools=[buscar_curso])
async def main():
    if not os.getenv('OPENAI_API_KEY'): raise RuntimeError('Defina OPENAI_API_KEY')
    r=await Runner.run(agent,'Quantas vagas há em Agentes de IA?')
    print(r.final_output)
if __name__=='__main__': asyncio.run(main())

5. Verificar resultado

Confira se aparece “30 vagas” e se a ferramenta foi invocada. Teste curso inexistente, instrução maliciosa e ausência de chave. O SDK não foi executado aqui com API real.

6. Erros e segurança

Chave ausente: configurar variável de ambiente. Não chamou ferramenta: conferir descrição, modelo e traces. Risco: não disponibilizar ferramentas de escrita nem credenciais ao modelo. Registre traces com retenção segura.

7. Avaliação e alternativas

Compare acerto das chamadas, custo real de tokens, latência e consistência com Python fixo e Ollama. Se precisar de grafos persistentes, avalie LangGraph; se precisar de canais, runtime OpenClaw.

Roteiro de implementação verificável — Agents SDK

O que será construído?

Agente programado com ferramenta Python. O caso comum utiliza informações fictícias de cursos; não envia dados institucionais reais.

Arquitetura e responsabilidades

Solicitação simulada
        ↓
Agents SDK — coordenação / ambiente de execução
        ↓
Ferramenta consultar_curso (lógica determinística)
        ↓
Resultado validado → registro → resposta

A aplicação invoca Runner; Runner gerencia o ciclo do agente; function_tool só executa uma função com permissões limitadas. O Runner conduz as chamadas ao modelo e ferramentas, enquanto a função Python impõe as regras.

Pré-requisitos e arquivo do projeto

Antes de instalar, verifique versão da documentação oficial, Python ou Docker quando indicado, permissões restritas e custos do provedor. Artefato de apoio: laboratorios/comparacao-seis-abordagens/agents_sdk.py. O código encontra-se no pacote do Agente.IA.

Instalação e execução orientada

Crie ambiente virtual, instale openai-agents, defina OPENAI_API_KEY somente no seu ambiente, execute o script do laboratório e observe se a chamada de ferramenta retorna dados do catálogo sintético. Não envie documentos reais.

Resultado esperado e testes

Teste A: curso conhecido → dados correspondentes ao catálogo; teste B: curso desconhecido → sinalização de inexistência; teste C: tentativa de consultar documento não autorizado → bloqueio, sem execução privilegiada. Registre também quais ferramentas foram realmente chamadas.

Erros frequentes

Sem chave de API ou créditos, execute o baseline offline; a execução com SDK é opcional e pode gerar custos.

Segurança e avaliação

Princípio de menor privilégio, dados fictícios, segredos fora do código, aprovação de ações sensíveis e logs sem dados pessoais. O modelo não define nem altera regras de autorização. Compare cada resposta com o baseline determinístico.
