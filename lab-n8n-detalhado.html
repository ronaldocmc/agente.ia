n8n — laboratório: workflow versus agente com Ollama

Versão expandida: abrir implementação detalhada, com roteiro de execução e testes →

Quem orquestra? Na automação, o n8n determina a sequência. Na versão agêntica, o n8n dispara e registra o processo, enquanto o nó AI Agent seleciona chamadas à ferramenta, auxiliado pelo Ollama.

Chat Trigger n8n
↓
AI Agent no n8n
↓
Ollama seleciona consulta
↓
Tool consultar_curso
↓
Resposta da ferramenta
↓
Resposta final registrada

1. Objetivo e resultado

Receber a pergunta “Quantas vagas há em Agentes de IA?”, consultar um catálogo fictício e responder 30 vagas, com origem identificada. A resposta não pode inventar dados nem executar alterações externas.

2. Dados e arquitetura da experiência

Os arquivos comuns ficam em laboratorios/comparacao-seis-abordagens/: catalogo.json, regras.py, consultar.py e SKILL.md. A regra de negócio é executada por código, nunca decidida pelo prompt.

3. Instalação prática

Instale Docker e Ollama no host, baixe um modelo compatível com tool calling e importe o workflow JSON incluído no pacote.

ollama pull qwen3:4b
cd laboratorios/n8n-ollama-agente
docker compose up -d

4. Configuração dos nós

Chat Trigger → AI Agent; conecte Ollama Chat Model via ai_languageModel e consultar_curso via ai_tool. O código da ferramenta está no diretório laboratorios/n8n-ollama-agente/. Se n8n roda em Docker, configure a credencial do Ollama no endereço do host apropriado, não em localhost do contêiner.

5. Teste e observação

Compare pergunta sobre vagas, curso inexistente e prompt injection. Inspecione a execução de cada nó. O resultado certo exige que a ferramenta seja chamada antes de responder.

6. Erros, segurança e avaliação

Falha de conexão: revisar rede Docker. Modelo sem ferramentas: escolher checkpoint suportado. Resposta inventada: validar tool trace. Não exponha editor n8n e credenciais em rede pública. O arquivo JSON já existe, mas integração real ainda não foi executada aqui.

Roteiro de implementação verificável — n8n

O que será construído?

Workflow e agente Ollama. O caso comum utiliza informações fictícias de cursos; não envia dados institucionais reais.

Arquitetura e responsabilidades

Solicitação simulada
        ↓
n8n — coordenação / ambiente de execução
        ↓
Ferramenta consultar_curso (lógica determinística)
        ↓
Resultado validado → registro → resposta

n8n executa gatilhos/nós; o nó AI Agent decide qual tool usar; a função local determina acesso e resultado. n8n decide a sequência e controla gatilhos; o modelo dentro do agente decide se solicita a ferramenta. A ferramenta valida a consulta.

Pré-requisitos e arquivo do projeto

Antes de instalar, verifique versão da documentação oficial, Python ou Docker quando indicado, permissões restritas e custos do provedor. Artefato de apoio: laboratorios/n8n-ollama-agente/workflow-n8n-agente-ollama.json. O código encontra-se no pacote do Agente.IA.

Instalação e execução orientada

Instale Docker e Ollama; execute docker compose; carregue um modelo com tool calling; importe o JSON em Workflows > Import from File; configure o endereço do Ollama visível a partir do contêiner; execute três consultas fictícias e compare com o workflow sem LLM.

Resultado esperado e testes

Teste A: curso conhecido → dados correspondentes ao catálogo; teste B: curso desconhecido → sinalização de inexistência; teste C: tentativa de consultar documento não autorizado → bloqueio, sem execução privilegiada. Registre também quais ferramentas foram realmente chamadas.

Erros frequentes

O endereço localhost do contêiner não é o host; use o nome do serviço ou host.docker.internal quando apropriado.

Segurança e avaliação

Princípio de menor privilégio, dados fictícios, segredos fora do código, aprovação de ações sensíveis e logs sem dados pessoais. O modelo não define nem altera regras de autorização. Compare cada resposta com o baseline determinístico.
