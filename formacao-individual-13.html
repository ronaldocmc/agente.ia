ETAPA 01

O que é Paperclip?

Paperclip é uma camada de controle organizacional, com servidor Node.js, interface React e persistência PostgreSQL. Não é um LLM nem substitui o runtime do agente.

Diretor humano→Paperclip: objetivos, tarefas, orçamento→Adaptador→Runtime + ferramentas

Company delimita uma organização; goal define o resultado; project agrupa trabalho; issue registra uma tarefa; heartbeat aciona uma execução. O adaptador conecta a execução ao plano de controle.

ETAPA 02

Objetivos e entregas

Construir o Escritório Virtual Alfa, organização fictícia com quatro agentes: Coordenador (CEO), Triagem, Analista e Revisor. O diretor humano autoriza o encerramento.

Entregar organograma, registros de tarefas, validação determinística, parecer independente, decisão humana e relatório de custos. CP01–CP06 obrigatórios; CP07 servidor opcional.

ETAPA 03

Pré-requisitos e ambientes

Node.js 24.11 ou superior, npm, Python 3, terminal e navegador. Para Codex ou Claude Code, instalar e autenticar o runtime conforme sua documentação. No Windows, preferir WSL2 Ubuntu para manter servidor e runtimes no mesmo ambiente Linux. Não é necessária GPU para inferência remota.

node --version
npm --version
python3 --version

Não use conta de produção, diretório pessoal ou chaves em arquivos versionados.

ETAPA 04

Instalação local passo a passo

  1. Instale Node.js LTS compatível e confirme a versão.
  2. Em usuário Linux não root, execute o onboarding oficial.
  3. Abra a URL indicada no terminal (normalmente localhost:3100).
  4. Mantenha o modo local restrito ao loopback; não exponha a porta.
npx paperclipai@latest onboard --yes

Registre a versão instalada e fixe-a nas próximas reproduções. O PostgreSQL embarcado dispensa configuração externa no percurso local. CP01: interface acessível e versão registrada.

ETAPA 05

Materiais e referência determinística

Baixe o guia e arquivos. Use um diretório exclusivo para o projeto. Os dados são fictícios e não exigem LLM.

python3 validar.py

Resultado esperado: D01 → TI, D02 → SECRETARIA, D03 → REVISAR, D04 → DUPLICADA, D05 → REVISAR. CP02: referência JSON gerada. Não altere o conjunto original.

ETAPA 06

Criar organização e primeiro agente

  1. Crie a company Escritório Virtual Alfa.
  2. Defina o objetivo: classificar demandas fictícias com rastreabilidade e revisão humana.
  3. Crie o primeiro agente, Coordenador, com papel CEO.
  4. Escolha adaptador Codex ou Claude Code conforme ambiente disponível; conecte o provedor, configure e execute Run test.
  5. Em Identity, configure AGENTS.md usando as instruções de apoio.
  6. Em Audit → Budgets, configure limites antes de atribuir tarefas. Mantenha heartbeat periódico desligado.

CP03: organização criada, agente configurado e teste de conexão registrado.

ETAPA 07

Criar agentes especializados e organograma

Em Agents → New Agent, crie Triagem, Analista e Revisor. Escolha adaptador e ambiente, execute Run test e finalize. Em Overview, confirme que reportam ao Coordenador. Em Identity, aplique as instruções individuais do pacote.

Triagem

Valida e classifica dados.

Analista

Propõe encaminhamentos.

Revisor

Confere fontes e divergências.

Não conceda acesso a e-mail, GitHub de produção ou sistemas externos. CP04: quatro identidades e hierarquia verificáveis.

ETAPA 08

Projetos, tarefas e delegação

Crie um projeto de laboratório, configure seu workspace conforme o adaptador e disponibilize os arquivos. Crie uma issue para o Coordenador com o objetivo e critérios de aceite. Inicialmente, faça a delegação supervisionada: crie três issues filhas, atribuindo uma a cada agente. Selecione dependências quando disponíveis.

IssueResponsávelEntrega
TriarTriagemtriagem.json
AnalisarAnalistaparecer.md
RevisarRevisorrevisao.md

Se os workspaces forem isolados, transfira os artefatos explicitamente pela issue ou mecanismo aprovado. Uma menção não equivale a atribuição.

ETAPA 09

Heartbeat e execução supervisionada

Atribuir trabalho pode disparar execução mesmo com timer desligado. Observe Agents → Runs e o histórico da issue. Para teste isolado use Run now, sem duplicar uma execução ativa.

npx paperclipai heartbeat run --agent-id ID_DO_AGENTE --source on_demand --trigger manual

O comando requer contexto/autenticação válidos. Observe checkout, logs, status, artefatos e custo. Se houver falha, registre o erro e não marque a tarefa como concluída. CP05: trilha real de execução e três entregas.

ETAPA 10

Skills, ferramentas e aprovação humana

AGENTS.md define responsabilidades; HEARTBEAT.md pode definir rotina recorrente; uma skill descreve procedimento reutilizável; o código Python executa a regra objetiva. O runtime interpreta instruções e invoca ferramentas. O Paperclip coordena e registra a atividade.

Cadastre a skill de triagem do pacote na biblioteca da organização conforme a versão e habilite apenas nos agentes necessários. Configure revisão/aprovação no fluxo se disponível; caso contrário, deixe a issue em revisão até decisão explícita do operador. Não conecte serviços externos. CP06: decisão humana registrada e divergências corrigidas.

Registre entrada, saída observada, evidência e aprovação. A referência é independente; a resposta do LLM não é a verdade de referência.

ETAPA 12

Segurança, privacidade, custos e licença

O código Paperclip é MIT segundo o repositório oficial; modelos, runtimes e serviços podem ter termos e cobranças próprios. Registre custo reportado e compare com a fatura do provedor, quando acessível. Limites internos não garantem cobertura de gastos externos.

Use menor privilégio, segredos protegidos, dados sintéticos, ambientes separados e aprovação humana. Não confunda workspace com sandbox. Desative telemetria se necessário com PAPERCLIP_TELEMETRY_DISABLED=1, conforme documentação.

ETAPA 13

Opcional: Ubuntu 24.04 em servidor

Em VM isolada, usuário sem root e Node.js compatível, execute o onboarding em loopback. Para acesso remoto use modo autenticado, rede privada e política de TI. Consulte o guia oficial Docker para produção, PostgreSQL externo, volumes, backup e recuperação. Não reutilize banco, porta ou credenciais de produção.

npx paperclipai@latest onboard --yes --bind tailnet

Use o preset tailnet somente se a rede correspondente estiver configurada. Não aplique diretamente em servidor institucional. CP07: autenticação, acesso restrito, logs e restauração comprovados.

ETAPA 15

Quando utilizar e quando evitar

TecnologiaEscolha quando
PaperclipHá organização persistente, papéis, delegação e governança.
OpenBotAmbiente colaborativo e workspaces são centrais.
OpenClaw / HermesÉ necessário runtime de agente persistente e ferramentas.
CrewAI / LangGraphÉ necessária lógica multiagente programável.
n8nIntegrações e fluxos explícitos predominam.

Evite Paperclip para scripts simples, fluxo determinístico curto ou agente isolado sem necessidade de governança. Pode complementar runtimes e workflows por adaptadores, sem presumir integração nativa universal.

ETAPA 16

Avaliação, rubrica e extensão

Entregue arquitetura (20%), execução rastreável (30%), testes (25%), segurança e custos (15%), reprodutibilidade (10%). Compare com execução manual do validador. Meça acertos por demanda, divergências, número de runs e custo reportado.

Desafio avançado: integrar um executor Python por adaptador de processo/HTTP após estudar o contrato oficial; comparar com n8n; avaliar exportação/importação da organização sem segredos. Relacione o caso ao Escritório Virtual.
