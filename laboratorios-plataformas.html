Laboratórios de agentes: plataforma pronta, código e execução local

Objetivo. Ensinar o mesmo problema por três caminhos complementares: (A) plataforma pronta com ferramentas que a conta permite; (B) código próprio; (C) inferência local. Nenhum laboratório obrigatório exige conta, assinatura ou chave comercial.

Caso transversal: consulta do certificado do curso unesp.IA (M12, T1) com dados sintéticos. A fonte da verdade é uma função de domínio com regras fixas: somente o titular pode consultar; frequência mínima de 75%; situação regular. O LLM jamais concede certificado nem redefine autorização.

1. Três caminhos, mesma regra

CaminhoComponentesEntregaDependência/custo
A — Plataforma prontaChatGPT com plugins/conexões elegíveis; Gemini com recurso de agente disponível; Claude com Cowork, skills e conectores conforme planoRoteiro de configuração, simulação e evidênciasDisponibilidade variável, possíveis limites e cobranças; não obrigatório
B — Código próprioPython, regra de negócio, tests, OpenAI Agents SDK opcional, n8n opcionalCódigo executável sem LLM; variante API condicionalSem API no baseline; API pode cobrar
C — Modelo localOllama + modelo compatível com tool calling + PythonAgente local com loop de ferramenta, validação e limite de ciclosSem cobrança por chamada local; hardware e energia não são gratuitos

2. Roteiros complementares: ChatGPT, Gemini e Claude

2.1 ChatGPT — execução de ações por plugin ou recurso disponível

Exercício: simular a consulta com um arquivo CSV sintético e instruções de não emitir certificados. Se a conta oferecer plugins e integração com aplicativo de teste, mapear a função consultar_certificado como ferramenta com entrada email e saída estruturada. Registrar necessidade de autorização e confirmação. Sem integração, o experimento é de interpretação/planejamento, e não demonstra tool calling real.

Cuidado editorial (novembro/2026): GPTs personalizados estão em transição para plugins; a criação de novos GPTs em contas pessoais não está disponível. O Agente.IA não recomenda iniciar laboratório obrigatório que dependa da criação de um GPT. Ver aviso oficial sobre migração.

2.2 Gemini — aplicativo/ambiente e ADK são experiências distintas

Exercício: pedir ao Gemini uma proposta de plano de consulta e validar manualmente contra os casos sintéticos. Se houver recurso de agente/conector habilitado, executar em ambiente de testes com permissões mínimas. Como alternativa programável, estudar o Google ADK; não confundir Gemini como modelo, aplicativo Gemini e agente implementado com ADK.

2.3 Claude — Skills e Cowork com ferramentas habilitadas

Exercício: criar uma skill de procedimento de consulta, sem dados reais, e solicitar que o Claude explique a decisão. Se Cowork e conectores estiverem disponíveis, executar operação somente de leitura com autorização do titular. Se não estiverem, usar apenas a simulação; não afirmar que uma ação externa ocorreu. A documentação de skills descreve requisitos e disponibilidade.

3. Agente local em Ollama

Instalar Ollama; baixar um modelo com suporte comprovado a chamadas de ferramentas (exemplo documentado: ollama pull qwen3; conferir variante e requisitos antes da aula). Executar python ollama_agente.py no diretório laboratorios/lab19_independente/. O script usa API local localhost:11434 e biblioteca padrão do Python, sem credencial comercial. Escolher outra variante se hardware insuficiente.

O aluno observa: o modelo escolhe uma ferramenta, a aplicação valida argumentos e identidade, a função de negócio retorna um status, e só então o modelo formula a resposta. Se o modelo responder sem ferramenta, a aplicação sinaliza o desvio; não inventa aprovação.

4. Protocolo comparativo e reprodutibilidade

DimensãoMétricaProcedimento
QualidadeAcurácia de status, taxa de tool use correta, schema válidoCasos sintéticos fixos e referências da função
CustoTokens, custo monetário, tempo de máquinaRegistrar preços vigentes; não equiparar zero taxa API a custo zero
ReprodutibilidadeParâmetros, versões, saídas em repetiçãoHash do dataset, modelo e prompts versionados
SegurançaTaxa de recusa correta, acesso indevido e injeçõesTestes de autorização no backend; jamais confiar na identificação pelo prompt
ManutenibilidadeTempo de alteração de regra e número de pontos editadosComparar procedimento direto × skill sob a mesma função de domínio

5. Critérios de aceite para as aulas

  1. O baseline determinístico funciona offline e passa nos testes.
  2. O aluno distingue uma resposta simulada de uma ação efetuada com ferramenta.
  3. Nenhuma variante consulta certificados reais, nem executa envio de mensagens.
  4. Modelos e plataformas comerciais são optativos e sempre têm caminho alternativo.
  5. Os relatos incluem versões, limitações, erros e custos observados, sem comparar execuções não realizadas.
