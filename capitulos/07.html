7. Implementações reais e públicas no GitHub

A pesquisa do guia original identificou 20 estudos de código, exemplos, templates e projetos. Um deles retoma um repositório já apresentado (n8n Starter Kit), com finalidade didática diferente; portanto, 20 estudos não equivalem a 20 repositórios distintos. O capítulo 21 acrescenta referências recentes.

É necessário distinguir uma implementação pública de referência de um produto comprovadamente implantado em produção.

Os repositórios demonstram abordagens e recursos técnicos, mas nem todos representam sistemas completos, seguros e preparados para utilização empresarial.

G01 — OpenAI Agents SDK: padrões de coordenação #

Repositório de exemplos oficiais

Apresenta padrões de execução determinística, roteamento, handoff, agentes como ferramentas e paralelismo.

É uma boa referência para compreender a diferença entre um agente gerente, que mantém o controle, e uma arquitetura em que o atendimento é transferido a outro especialista.

Experimento proposto: adaptar os exemplos para agentes de estoque, vendas e finanças, registrando as decisões e transferências.

G02 — OpenAI Agents SDK: primeiro agente com ferramentas #

OpenAI Agents SDK para Python

O repositório contém a biblioteca oficial e exemplos básicos de agentes com ferramentas.

Permite estudar Agent, Runner, ferramentas tipadas, execução e rastreamento.

Experimento: criar um agente que consulta estoque fictício e comparar sua implementação com uma função Python convencional.

G03 — Google ADK Recipes #

Google ADK Recipes

Coleção de receitas para desenvolvimento de agentes, incluindo memória, RAG, autenticação, segurança e aplicações especializadas.

O material serve como ponto de partida e não deve ser interpretado automaticamente como solução pronta para produção.

Experimento: construir agentes especializados na classificação de mensagens de CRM.

G04 — Google ADK: triagem com especialistas #

Google ADK Python

Os exemplos do SDK permitem estudar agentes especializados, planejamento, paralelismo e coordenação.

Experimento: implementar um sistema de triagem em que um coordenador distribui solicitações para especialistas em vendas, suporte e financeiro.

G05 — Claude Agent SDK: Quick Start #

Claude Agent SDK Python

O SDK apresenta recursos para execução de agentes com ferramentas.

É importante estudar permissões, limites de leitura e escrita, execução de tarefas e mensagens produzidas pelo agente.

Experimento: permitir que o agente consulte arquivos fictícios e produza um relatório em diretório isolado.

G06 — LangGraph Retrieval Agent Template #

LangGraph Retrieval Agent Template

Apresenta uma arquitetura de recuperação de informações com indexação, consulta e utilização de documentos.

Experimento: construir um agente que responde perguntas sobre documentos institucionais, identificando as fontes utilizadas.

G07 — LangGraph: núcleo de orquestração #

LangGraph

Framework para grafos de execução, persistência, estado, interrupção e retomada.

Experimento: criar um processo de compra que só possa avançar para a emissão do pedido após aprovação humana.

G08 — CrewAI: agentes e workflows #

CrewAI

Apresenta estruturas para agentes especializados, equipes e fluxos de execução.

Experimento: comparar uma arquitetura com agente único e ferramentas com outra baseada em três agentes especializados.

G09 — CrewAI Examples #

CrewAI Examples

Galeria de demonstrações com diferentes aplicações.

Experimento: estudar a organização de responsabilidades, entradas, saídas e comunicação entre agentes, adaptando o exemplo para o domínio comercial.

G10 — PydanticAI: atendimento com saída estruturada #

PydanticAI

O projeto inclui exemplos que utilizam dependências tipadas, ferramentas e respostas estruturadas.

Experimento: criar um agente de CRM que classifica solicitações e produz um resultado validado por esquema, sem alterar registros automaticamente.

G11 — n8n Self-hosted AI Starter Kit #

n8n Self-hosted AI Starter Kit

Projeto com Docker Compose que integra n8n, Ollama, Qdrant e PostgreSQL.

É uma referência prática para compreender como automação, modelos locais, banco relacional e recuperação de informações podem funcionar em um mesmo ambiente.

Experimento: criar um workflow de consulta ao estoque, classificação e notificação.

O projeto não deve ser considerado pronto para produção sem configuração adicional de segurança, segredos, backups e operação.

G12 — n8n: exemplos de IA avançada #

Documentação de IA no n8n

Apresenta materiais sobre agentes, ferramentas, memória e integração de sistemas.

Experimento: comparar um workflow determinístico com outro que utiliza um agente para selecionar ferramentas.

G13 — MCP Python SDK #

MCP Python SDK

Biblioteca oficial para desenvolvimento de componentes MCP.

Permite estudar servidores, clientes, ferramentas, recursos, contratos e mecanismos de comunicação.

G14 — MCP Servers #

MCP Reference Servers

Reúne servidores de referência com diferentes capacidades.

Experimento: estudar como recursos e ferramentas são expostos e quais permissões são necessárias.

G15 — Agent Skills #

Agent Skills

Especificação e exemplos de capacidades reutilizáveis baseadas em instruções e arquivos auxiliares.

G16 — OpenClaw #

OpenClaw

Ambiente agêntico que integra ferramentas, sessões, canais, skills e capacidades de execução.

G17 — Hermes Agent #

Hermes Agent

Runtime de agentes com ferramentas, memória, automações e capacidades de delegação.

G18 — Flowise #

Flowise

Plataforma visual importante para estudar fluxos de aplicações com LLMs, agentes, ferramentas e recuperação de informações.

G19 — Langflow #

Langflow

Ambiente de desenvolvimento visual para fluxos com modelos, ferramentas e agentes.

Experimento: implementar um fluxo RAG, analisar seus componentes e comparar sua organização com uma implementação Python.

G20 — Arquitetura local com modelos e automação #

Ambiente integrado de IA local

Este último estudo retoma o Starter Kit do n8n, agora com foco na infraestrutura.

Experimento: estudar a comunicação entre contêineres, volumes, rede, persistência, autenticação e execução de modelos locais.

Posteriormente, integrar uma API FastAPI própria e verificar o fluxo completo de requisições.

7.1 Como analisar corretamente um projeto do GitHub #

Antes de copiar um código, o aluno deve verificar licença, manutenção, dependências, arquitetura, instruções de instalação, credenciais, testes, exemplos, permissões e riscos.

É importante identificar se o código representa uma demonstração, um template, uma biblioteca ou uma aplicação preparada para produção.

7.2 Como comparar diferentes tecnologias #

Uma comparação cientificamente válida precisa utilizar a mesma tarefa e condições equivalentes.

Por exemplo, podemos classificar os mesmos 100 registros de um observatório utilizando regras, um agente com LLM, um agente com RAG e um sistema multiagente.

Devemos controlar dados, ferramentas, modelos, versões, orçamento e métricas.

Uma única demonstração bem-sucedida não comprova superioridade de uma tecnologia.

Agente.IA · Documentação integrada · Conteúdo técnico-didático em evolução · Informações de fornecedores e versões exigem revalidação.

Como transformar referências do GitHub em um agente implementado

Os repositórios deste capítulo são referências de código, não prova de que uma aplicação completa está pronta. Para estudar um deles, compare o orquestrador, a declaração de ferramentas, o estado, o tratamento de erros, as permissões e os testes.

Experimento comum: consulta fictícia de cursos em seis tecnologias. Comece pela página de laboratórios comparativos, depois consulte Agents SDK, LangGraph, n8n, Hermes, OpenClaw e Grok Bot.

Ao analisar um repositório, registre commit, licença, versão, dependências, comando executado, saída observada e problemas encontrados. Para evitar dependência de plataformas, mantenha o baseline local determinístico.
