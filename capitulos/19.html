19. Interoperabilidade: de MCP a A2A, AG-UI, A2UI e ACP

A arquitetura de agentes está ampliando o foco da integração com ferramentas para a integração entre agentes, usuários, ambientes gráficos e serviços.

19.1 Comparação de protocolos e padrões #

Padrão Relação que padroniza Exemplo Principal cuidado
MCP Aplicação/agente ↔ ferramentas, recursos e prompts Consultar dados via servidor de ferramentas Permissões, credenciais e conteúdo não confiável
A2A Agente ↔ agente independente Agente comercial delega previsão a outro serviço Autenticação, confiança e contratos de tarefa
AG-UI Backend agêntico ↔ interface de usuário Frontend mostra estado e pede aprovação Privacidade, eventos, estado consistente
A2UI Agente → descrição declarativa da interface Agente apresenta tabela/formulário gerado Catálogo autorizado de componentes
ACP Editor de código ↔ agente de programação IDE comunica alterações e ações ao agente Permissões de arquivo e execução
API/HTTP Serviço ↔ serviço Consultar ERP ou CRM Autenticação, versionamento e limites
Webhook Evento → aplicação receptora Venda ativa verificação de estoque Assinatura e idempotência

19.2 MCP: integração vertical de capacidades #

MCP facilita expor ferramentas a hosts compatíveis. O cliente deve validar argumentos, permissões e respostas; conteúdo retornado por uma ferramenta não é uma nova instrução de maior prioridade. A documentação oficial do SDK Python v2 confirma a alteração de FastMCP para MCPServer e outras mudanças de protocolo. Exemplos para v1 e v2 não devem ser misturados. Fontes: MCP Python SDK v2 e guia de migração.

19.3 A2A: cooperação entre agentes independentes #

O protocolo Agent2Agent (A2A) oferece uma especificação para descoberta de capacidades, mensagens, tarefas e colaboração entre agentes de diferentes implementações. Para estudar o protocolo, use o repositório oficial a2a-samples. Um agente externo deve ser considerado não confiável até que identidade, autorizações, contratos e conteúdo sejam validados.

Exemplo: o agente de CRM atende o cliente e solicita ao agente de logística uma estimativa de entrega. A2A permite estruturar essa cooperação entre sistemas independentes; não substitui o controle de acesso ao banco de dados de logística.

19.4 AG-UI e A2UI: relacionamento com a interface #

AG-UI padroniza eventos de interação e estado entre aplicações frontend e agentes, útil para streaming, confirmação de ações e visualização de progresso. A2UI oferece uma representação declarativa de interfaces geradas por agentes, com componentes que a aplicação decide como renderizar. A2UI foi apresentado como tecnologia em evolução; não se deve aceitar componentes, scripts ou ações arbitrárias sem validação.

19.5 Exemplo integrado dos protocolos #

Imagine um gerente solicitando a análise de uma loja: a interface utiliza AG-UI para mostrar o progresso; o agente coordenador acessa dados via MCP; um especialista independente de demanda recebe uma tarefa via A2A; o resultado pode retornar como tabela declarativa A2UI; a aplicação valida tudo e exige aprovação humana antes de qualquer pedido de compra. A presença de vários protocolos não é obrigatória: cada um deve ser usado somente quando a interoperabilidade justifica seu custo.
