6. Capacidades fundamentais: ferramentas, MCP, skills, RAG e memória

6.1 Ferramentas e tool calling #

Uma ferramenta é uma operação invocável por um sistema.

Exemplos:

consultar_estoque(produto_id)
consultar_pedido(pedido_id)
calcular_previsao(produto_id)
gerar_relatorio(periodo)

Uma ferramenta deve possuir entradas, saídas, responsabilidades e tratamento de erros bem definidos.

Quando um LLM solicita a execução de uma função, temos uma utilização de tool calling.

O modelo pode decidir solicitar a ferramenta, mas normalmente é a aplicação que valida e executa a operação.

6.2 APIs #

Uma API define um contrato para comunicação entre sistemas.

Por exemplo, uma API de estoque pode disponibilizar:

GET /produtos/10/estoque

O agente pode utilizar essa operação para consultar a quantidade disponível.

A API é um mecanismo de integração; não determina, sozinha, a existência de um agente.

6.3 MCP — Model Context Protocol #

O MCP é um protocolo de interoperabilidade que permite às aplicações de IA acessar ferramentas, recursos e prompts disponibilizados por servidores compatíveis.

Uma arquitetura MCP envolve três papéis principais:

Host: aplicação que utiliza os recursos.

Cliente MCP: componente que estabelece a comunicação.

Servidor MCP: disponibiliza ferramentas, recursos e prompts.

Exemplo:

Um servidor MCP pode expor a ferramenta consultar_estoque. Diferentes agentes ou aplicações compatíveis podem acessá-la mediante os controles apropriados.

O MCP não substitui bancos de dados ou APIs existentes e não elimina autenticação e autorização.

A documentação oficial confirma que o SDK Python do MCP entrou na linha v2 em 2026, com mudança da classe FastMCP para MCPServer (importação from mcp.server.mcpserver import MCPServer). Os exemplos exigem conferência com a versão instalada; código v1 não deve ser misturado com v2. Veja guia oficial de migração.

Documentação: Model Context Protocol.

6.4 Skills #

Aprofundamento: guia completo de Skills, SKILL.md, segurança e laboratórios →

Uma skill é uma capacidade procedural reutilizável.

Ela pode incluir instruções, arquivos de referência, scripts, padrões de saída e critérios de validação.

Exemplo de estrutura:

skills/
└── relatorio_estoque/
    ├── SKILL.md
    ├── scripts/
    │   └── calcular_cobertura.py
    └── referencias/
        └── politica_compras.md

O arquivo SKILL.md pode explicar:

  • Quando a skill deve ser utilizada.
  • Quais dados são necessários.
  • Quais ferramentas podem ser chamadas.
  • Qual sequência de atividades deve ser seguida.
  • Como validar os resultados.
  • Qual formato de relatório deve ser produzido.
  • Quais ações exigem aprovação.

Uma skill não é necessariamente uma ferramenta. Ela pode orientar a utilização de várias ferramentas.

Documentação: Agent Skills Specification.

6.5 RAG — Retrieval-Augmented Generation #

RAG é uma abordagem que permite recuperar informações externas relevantes para fundamentar respostas geradas por um modelo.

Um pipeline comum contém:

  1. Coleta e extração de documentos.
  2. Limpeza e preparação do conteúdo.
  3. Fragmentação em trechos.
  4. Construção de índices, eventualmente utilizando embeddings.
  5. Recuperação dos trechos mais relevantes.
  6. Filtragem e reordenação dos resultados.
  7. Inserção do contexto recuperado na solicitação ao modelo.
  8. Geração de resposta.
  9. Verificação de evidências e avaliação.

Não precisamos obrigatoriamente de recuperação vetorial em todos os problemas.

É possível comparar recuperação lexical, vetorial, híbrida e técnicas de reranking.

6.6 Memória #

É necessário distinguir três conceitos.

Memória conversacional: informações relevantes das interações anteriores.

Estado de execução: informações sobre o andamento de uma tarefa, etapas concluídas e aprovações pendentes.

Memória persistente: informações mantidas entre sessões, respeitando políticas de relevância, retenção e segurança.

Uma aplicação não precisa de banco vetorial para ter memória.

PostgreSQL e outras estruturas podem armazenar estados, preferências autorizadas e históricos.

6.7 Métodos computacionais clássicos #

Nem todo agente exige LLM.

No varejo, podemos utilizar séries temporais, regressão, árvores de decisão, classificação e otimização.

No CRM, regras e classificadores podem resolver parte da triagem.

No observatório, podemos iniciar com coleta, deduplicação e regras de relevância.

Esses métodos são importantes também como baselines experimentais para avaliar se a utilização de LLMs realmente acrescenta valor.
