4. Arquitetura de referência para sistemas agênticos

Uma aplicação de agentes pode ser organizada em seis camadas conceituais. Isso não significa que cada camada precise ser implementada como um serviço independente.

4.1 Canais e interfaces #

São os meios pelos quais usuários e sistemas interagem.

Exemplos: chat web, aplicativo, WhatsApp, e-mail, voz, APIs, sistemas corporativos e dispositivos IoT.

Os canais transportam informações e eventos, mas não devem concentrar políticas críticas de segurança ou negócios.

4.2 Camada de aplicação #

Responsável por autenticação, identificação do usuário, sessões, validação de contratos, isolamento de organizações e controle de acessos.

Tecnologias possíveis: FastAPI, Django, Node.js, Express e outras.

4.3 Agente e orquestrador #

Interpretam objetivos, mantêm estado, selecionam ferramentas e coordenam a execução.

Podem ser implementados com OpenAI Agents SDK, Google ADK, Claude Agent SDK, LangGraph, CrewAI, PydanticAI ou componentes próprios.

4.4 Capacidades #

Incluem regras, ferramentas, skills, APIs, MCP, modelos de machine learning, LLMs, classificadores e algoritmos de otimização.

4.5 Dados e conhecimento #

Incluem bancos SQL e NoSQL, documentos, RAG, memória, índices vetoriais e eventos.

PostgreSQL, pgvector e Qdrant são exemplos de tecnologias que podem participar dessa camada.

4.6 Governança transversal #

Inclui segurança, LGPD, autenticação, auditoria, monitoramento, explicabilidade, avaliação e supervisão humana.

Esses controles devem acompanhar toda a execução.

4.7 Ciclo de execução #

Um fluxo de referência é:

Receber evento → validar usuário → recuperar estado → decidir próximo passo → validar permissão → executar ferramenta → verificar resultado → atualizar estado → responder ou solicitar aprovação → registrar métricas.

Cada etapa pode falhar. Por isso, a arquitetura deve considerar tentativas, timeouts, recuperação de estado, ações duplicadas e interrupções seguras.
