24. Conclusão: como decidir o que utilizar?

A escolha da tecnologia deve decorrer do problema, não da popularidade da ferramenta.

Para tarefas repetitivas e previsíveis, devemos começar com automação determinística.

Quando existem dependências entre atividades, precisamos considerar orquestração.

Quando é necessário interpretar situações, adaptar estratégias ou selecionar ações, podemos utilizar agentes inteligentes.

Para recuperar informações documentais, podemos empregar RAG.

Para integrar ferramentas e serviços, utilizamos APIs e MCP.

Para reutilizar procedimentos especializados, podemos desenvolver skills.

Para coordenar agentes, podemos recorrer a OpenAI Agents SDK, Google ADK, Claude Agent SDK, LangGraph, CrewAI ou outras abordagens apropriadas.

Para automação visual e integração de processos, n8n é uma alternativa relevante.

Para experimentar assistentes com ambientes agênticos integrados, podemos estudar OpenClaw e Hermes.

E quando as ações podem afetar clientes, sistemas, dados ou recursos financeiros, precisamos de governança, autorização, rastreabilidade e supervisão humana.

Recomendação arquitetural para os projetos do unesp.IA #

A base inicial que eu adotaria para desenvolvimento próprio seria:

Camada Tecnologia de referência
Linguagem principal Python
Backend e serviços FastAPI
Persistência PostgreSQL
Acesso aos dados SQLAlchemy e psycopg
Modelos GPT, Gemini, Claude ou modelos locais
Desenvolvimento de agentes OpenAI Agents SDK ou Google ADK
Orquestração complexa LangGraph, quando necessário
Sistemas multiagentes CrewAI, ADK ou LangGraph
Automação e integração n8n
Conhecimento RAG e pgvector, quando necessários
Capacidades reutilizáveis Skills
Interoperabilidade APIs e MCP
Implantação Docker e serviços de infraestrutura
Governança Políticas, logs, testes, métricas e supervisão

Essa arquitetura não obriga que todos os componentes estejam presentes em cada projeto.

Um observatório pode começar com Python, PostgreSQL e n8n. Um agente educacional pode utilizar um SDK com RAG. Um sistema comercial pode exigir um orquestrador mais elaborado, com aprovação humana e integração ao ERP.

O fundamental é que cada tecnologia tenha uma finalidade justificada.

O objetivo da formação em IA agêntica no unesp.IA não deve ser ensinar apenas a utilizar ferramentas, mas formar alunos capazes de compreender arquiteturas, projetar soluções, implementar mecanismos de decisão e avaliar cientificamente os resultados.

A melhor arquitetura não é aquela que utiliza o maior número de tecnologias. É aquela que resolve o problema com qualidade, confiabilidade, desempenho, segurança e complexidade adequados.

24.2 Transparência metodológica #

Os novos laboratórios Python/SQLite foram testados localmente; os exemplos com APIs de fornecedores, SDKs e aplicações comerciais dependem de configuração e validação externa. Estar publicado no GitHub não implica maturidade, estabilidade, segurança ou adequação para produção.
